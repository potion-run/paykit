This is the shortest path to a working billing model. It uses the in-memory
store and the manual provider, so it needs no database and no provider key.

## Declare the catalog

The catalog is plain data beside the stack. It is validated when the world is
built: a priced tier nothing can sell is an error.

```ts
import { Paykit } from "@potion.run/paykit";

const messages = Paykit.feature({ id: "messages", name: "Messages" });
const seats = Paykit.feature({ id: "seats", name: "Seats" });

const free = Paykit.plan({
  id: "free",
  grants: [Paykit.planItem(messages, { included: 100 })],
});

const pro = Paykit.plan({
  id: "pro",
  price: { amount: 1900, currency: "usd", interval: "month" },
  grants: [
    Paykit.planItem(messages, { included: 2_000, overage: "bill" }),
    Paykit.planItem(seats, { included: 5, resets: "never" }),
  ],
});

export const catalog = { features: [messages, seats], tiers: [free, pro] };
```

## Build the world

One declaration is read by the deploy, the Worker and the tests:

```ts
import { Paykit, type BillingStackProps } from "@potion.run/paykit";

export const billing = {
  catalog,
  providers: [Paykit.Manual()],
  store: Paykit.MemoryStore(),
} satisfies BillingStackProps;

// The deploy: validates the catalog and provisions the provider objects.
yield* Paykit.BillingStack("Billing", billing);

// The runtime: the model, the catalog, the guards and every tenant binding.
const World = Paykit.world({ ...billing, guards: Paykit.InsecureDevGuards });
```

`Paykit.world` is what a Worker serves. `Paykit.handler` mounts the paths every
deployment has — `/api`, `/admin`, `/checkout` and `/webhooks` — and leaves the
rest to `routes`.

## Check an account

`check()` is a read. It answers from the account's standing, not from the
provider. The account is bound once, when the verb is built.

```ts
const check = yield* Paykit.Check(account);
const answer = yield* check({ featureId: "messages" });
// { allowed, balance, standing, lockId? }
answer.balance.remaining; // 100; `null` for an unlimited item
```

## Record usage

```ts
const track = yield* Paykit.TrackUsage(account);
yield* track({ featureId: "messages", value: 1, idempotencyKey: requestId });
```

An `idempotencyKey` makes a retry the same usage record. A hold is an
addressable entity, so work in flight is reserved, then settled or released:

```ts
const hold = yield* Paykit.Hold(account);
const reservation = yield* hold({ feature: "messages", amount: 100, dedupeKey: turnId });

const settle = yield* Paykit.SettleHold(account);
yield* settle({ holdId: reservation.holdId, amount: 80, dedupeKey: `${turnId}:settle` });
// 20 returns to the allowance in the same command
```

## Read balances and controls

```ts
const balances = yield* Paykit.Balances(account);
const messagesBalance = yield* balances.get({ featureId: "messages" });

const customers = yield* Paykit.Customers(account);
const customer = yield* customers.get();

yield* customers.update({
  billingControls: {
    spendLimits: [{ featureId: "messages", amount: 5_000 }],
    usageAlerts: [{ featureId: "messages", at: 1_500 }],
  },
});
```

`Balance` carries its `breakdown` and, when the customer states one, the
`spendLimit` headroom. `track` past that ceiling refuses with
`SpendLimitExceeded` while the standing stays `good`; an alert records
`UsageAlertFired` and refuses nothing.
